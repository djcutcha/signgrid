# 法規役(legal)v1

看板1枚について、条例から次の4つを答える部品。

1. 自家用広告物か(自己の氏名・店名等を自己の事業所に表示するもの。許可不要の基準に収まるか)
2. 許可が要るか(3段階: 要 / 不要 / 要実測)
3. 許可期間(更新の周期)は何年か
4. 点検まわりの4つの義務(管理する / 点検する / 有資格者に点検させる / 行政へ報告する)は掛かるか(下の「4つの義務」)

答えには根拠条文(条・項・号と原文の抜粋)と confidence が付く。**条例の規則は AI が原文から抜き出し、手元の正解との照合(粗い存在照合)を通した第2版**(下の「検算」「限界」)。

## 使い方

```
# 住所 -> 自治体
python3 -m kanban_karte.legal.cli municipality --address "埼玉県越谷市南越谷1-1"

# 判定(寸法が分からなければ省略 = 要実測)
python3 -m kanban_karte.legal.cli judge --address "東京都豊島区見本町1-2-3" --use self --area 8.5 --height 3.2
python3 -m kanban_karte.legal.cli judge --address "..." --use self --area 8.5 --height 3.2 --place 商業地域 --kind 自立 --json

# 条例から規則を抽出し直す(Anthropic API。1自治体あたり概算 $0.1〜0.3)
python3 -m kanban_karte.legal.cli extract --municipality 越谷市 [--dry-run]
python3 -m kanban_karte.legal.cli extract --municipality all
```

Python から: `from kanban_karte.legal.judge import judge` → `judge("住所", use="self", area_m2=8.5, height_m=3.2, place=None, kind=None).to_dict()`。
`to_ledger_fields()` で台帳の `is_self_use` / `permit_required`(1/0/None。要実測は None)に直せる。

`--place` は 許可区域 / 禁止区域 / 用途地域名(商業地域 など。語の一覧は `legal/schema.py` の `ZONE_VOCAB`)。
`--kind` は 自立 / 壁面 / 突出 / 屋上 / 幕 / 旗 / 掛 など(台帳の種類の語でよい)。どちらも分かっていれば結論が絞れる。

## 出力

| 項目 | 内容 |
|---|---|
| `is_self_use_exempt` | 自家用の許可不要基準に収まるか。True / False / None(決められない)。用途が一般なら False |
| `permit_required` | `要` / `不要` / `要実測` |
| `permit_term_years` | 許可期間(年)。条例は「◯年以内」の上限で書かれているので上限。許可が不要なら None |
| `maintenance_duty` | 管理義務(良好な状態に保持)。`要` / `不要` / `要実測` |
| `inspection_duty` / `inspection_interval_years` | 点検する義務と周期(年。原文に周期が無ければ None) |
| `qualified_inspector` | 有資格者に点検させる義務。`要` / `努力`(努力義務)/ `不要` / `要実測`(全高不明で 4m 判定ができない時 等) |
| `report_duty` | 行政へ点検結果を報告する義務。`要` / `不要` / `要実測` |
| `duties` | 上の4つの画面用の1行(`title` / `value` / `text`(条文つき)/ `refs` / `reason`)。画面は `text` をそのまま出す |
| `inspection_required` | 後方互換。**= `report_duty`**(旧『点検』1本は、実際には許可・更新時の報告を指していた)。旧形式の規則だけは旧来の判定 |
| `citations` | 根拠。`source`(条例/施行規則)・`article`・`quote`(原文の抜粋)・`quote_verified` |
| `confidence` | 根拠に使った規則の confidence の最小値(AI の自己申告。検算前) |
| `branches` | `要実測` のとき「この区域・種類なら 要/不要」の場合分け |
| `notes` | 判定の前提・限界・条件欄の要点 |

## 判定の規則(保守側)

- 基準は「その面積以下なら許可不要」。境界値(面積 = 閾値)は基準内。
- 表示面積が None なら 要実測。高さ・地上高が None で、それを要する基準があれば 要実測(ただし面積が基準を超えていれば 要 が確定)。
- 適用できる基準が複数あり(種類・区域を絞っていない)、結論が割れるときは 要実測。全部の基準に収まれば 不要、全部超えれば 要。
- 壁面面積の何分の一 のように、数値(㎡・m)で書かれていない基準しか無い種類は 要実測(オーナー画面で種類=壁面と壁面の面積を渡した時は、取り込んだ壁面率で判定する。下の「種類ごとの判定」)。
- 一般の広告物は、許可区域では面積によらず許可が要る(4自治体とも条例の規定)ので 要。
- 点検まわりは 1 本に畳まず、4つの義務を別々に当てはめる(下の「4つの義務」)。**許可不要の自家用でも、点検する義務と有資格者の義務は条例どおりに判定**する。許可の要否に連動するのは `permit_required_only` が true の義務(行政への報告 等)だけ。

## 種類ごとの判定(壁面・袖。2026-11-04 追加、`kinds.py`)

オーナー画面(`by_kind=True`)だけで使う。台帳・影響の集計など今までの呼び出しは結果が変わらない(`by_kind` の既定は False)。

- 壁面: 壁面率(看板の面積 ÷ 取り付く壁面 1 面の面積。開口部を含む)を `wall_ratio_max`(用途地域で変わる時は `wall_ratio_by_zone`)で当てる。上限 = 壁面 × 比率。`wall_ratio_floor_m2` は「比率で出した面積が小さい時はこの面積まで可」(埼玉県)、`wall_ratio_cap_m2` は「比率以下かつこの面積以下」(越谷市の禁止地域で許可を受ける自家広告)。上端は `top_limit`= eave(軒高以下)/ wall(壁面の高さ以下)/ wall_with_overshoot_le_protrusion(壁面の高さを超える分は壁面からの出幅以下。さいたま市)。
- 袖(突出し): 壁面からの出幅 `protrusion_from_wall_max_m`、道路境界からの出幅 `protrusion_from_road_boundary_max_m`、道路上に突き出してよいか `road_protrusion_allowed`(自家用・許可不要の枠は false)、下端の地上高 `ground_clearance_sidewalk_min_m` / `ground_clearance_roadway_min_m`(車道上・歩道の無い道路)。東京都は道路境界からの出幅 0.5m 以下なら歩道上 2.5m(`ground_clearance_sidewalk_min_m_if_road_boundary_projection_le_0_5m`)。歩道か車道か分からない時は、厳しい方に収まれば適合、緩い方にも足りなければ超過、間は要実測。
- **境目は確定させない**: 基準の ±15%(基準が 0 m の時は ±0.15 m)に入る値は要実測。この幅は SignGrid の設計値で、条文の数値ではない。
- 結果は `kind_checks`(自家用で許可が要らない枠の基準)と `kind_permit_checks`(許可を受ける場合の基準= `permit_standards`)を分けて返す。基準(区域)で結論が割れる項目は要実測にし、基準ごとの結論を `branches` に残す。各行に条文(`kind_citations`。url・逐語か要旨か)と照合の区分(`verified`)。
- 道路占用(`road_occupancy`、条例の外): 袖が道路境界より道路側に出ていれば「要」、出ていなければ「不要の見込み」、境界の位置か出幅が無い・境目付近は「要確認」。文は「道路占用許可(道路法 第32条)が別に要る。道路使用許可(道路交通法 第77条)は警察署に確認」。道路の管理者ごとの数値(`by_manager`)は、公式で照合済み(official)の物だけ判定に使い、ほかは注意文だけ。
- 値の出どころ: `tools/merge_kinds_addendum.py` で `法規_壁面袖_rules追記案_2026-11-04.json`(4 自治体の公式サイト掲載の規則全文で照合、vault の照合記録)を取り込んだ。**値を入れたのは official のキーだけ**(78 個。数値の基準が無いと照合済みの null が 10 個)。copy(repo の写しのみ、6 個= 東京都の別表第2 の壁面率と「壁面から突出させない」)と unverified(1 個= 埼玉県の許可基準の道路境界からの出幅)は値を入れず `unverified_keys` に並べ、判定では「未確認= 要実測」。道路占用の by_manager は copy 4・unverified 3 で、数値は判定に使っていない。越谷市の引用は PDF の文字欠けを補った要旨(`verbatim: false`)。新しく足した `permit_standards`(埼玉県・越谷市・さいたま市)の `citations` は repo の写しに逐語で在る抜粋だけ(越谷市は 3 件が空。根拠は `kind_citations`)。

## 住所 → 自治体(`municipality.py`)

- 対象は東京都・埼玉県。区市町村名は表(東京 62、埼玉 63)の最長一致で取る。それ以外の都道府県は都道府県名だけを返す("四日市市" のような取り違えを避けるため、市区町村は取らない)。
- 都道府県名が無い住所は、全国で一意と分かっている名前(20区・越谷市・さいたま市)だけ補い、他は None(推測しない)。
- 条例の写しがあるのは 東京都 / 埼玉県 / 越谷市 / さいたま市。埼玉県の他の市町村は「埼玉県(市独自条例の有無は未確認)」として県条例を引く。東京都は区市町村によらず都条例(区市町村独自の条例の有無は調べていない)。

## 4つの義務(2026-11-02 追加)

「点検する義務」「有資格者に点検させる義務」「行政へ結果を報告する義務」は**別の義務**で、条例ごとに掛かり方が違う。以前の judge は `inspection_required` 1本(要/不要/要実測)に畳んでいたため、たとえば埼玉県で許可不要の自家用看板にも定期点検の義務があることを表せなかった(オーナー画面の「点検報告は許可を受けた看板が対象。…誰も点検していない可能性があります」は埼玉県では誤り。文は削除し、条例の義務を書く)。

| 義務 | 意味 | rules のキー | 値(judge) |
|---|---|---|---|
| 管理 | 補修その他必要な管理を行い、良好な状態に保持する(点検の義務ではない) | `maintenance_duty` | 要 / 不要 / 要実測 |
| 点検 | 劣化・損傷の状況を点検する(させる)。周期があれば年 | `inspection_duty` | 要 / 不要 / 要実測 |
| 有資格者 | 点検を屋外広告士等の資格者にさせる。義務 / 努力義務。東京都だけは『有資格の屋外広告物管理者を置く』義務(`duty_kind: "manager"`、任意キー、既定 `inspection`) | `qualified_inspector` | 要 / 努力 / 不要 / 要実測 |
| 行政への報告 | 点検結果を知事・市長へ報告・提出する(許可・更新の申請時 等) | `report_duty` | 要 / 不要 / 要実測 |

各項目は `citations` / `confidence` / `conditions`(`area_min_m2`・`height_min_m`(+`height_min_inclusive`: 「超える」は false)・`ground_clearance_min_m`・`permit_required_only`・`kinds` / `excluded_kinds`)を持つ。条件は AND(上端 4m 超 **かつ** 許可要 など)。寸法の OR は任意キー `any_of`(例: 高さ4m超 **または** 面積10㎡超。各要素は `*_min_m*` と `*_min_inclusive`)で表し、どれか1つ満たせば満たす(片方が超えていれば全高・面積の他方が不明でも確定、両方不明なら要実測)。`size_kinds` を置くと寸法条件はその種類にだけ掛かる(東京都: 広告塔・広告板だけ。アーチ・装飾街路灯は寸法によらない)。`area_min_inclusive: false` は面積『超』。種類で絞る条件は、種類が分からなければ 要実測。除外の種類は、種類が分からなければ除外しない(画面には除外される物を注に出す)。高さは上端の高さ(全高、地上から)。

### 4義務の再抽出(`legal.cli duties`)

`rules_extract.extract_duties` が、4つの義務**だけ**を `claude-opus-5-5`(effort medium)で抽出して既存の `rules_<自治体>.json` に混ぜる(許可の基準などの検算済みの数値は触らない。旧 `inspection` は外す)。プロンプトに4義務の定義と『許可不要の自家用にも掛かるか(`permit_required_only`)』の決め方を明示。**各自治体 2 回**走らせ(`runs/duties_<自治体>_<n>.json`、未追跡)、1 回目を採用。2 回の食い違いは『どの値も同じ。違うのは主語・トリガ・様式名の言い回しと、引用に含める条項の範囲だけ』(必須の値・条件・周期・資格者の層は 4 自治体とも一致)。引用は全部原文と一致(東京都 4/4、埼玉県 20/20、越谷市 14/14、さいたま市 17/17)。費用は 8 回で $2.45(入力 3.8〜7.5 万トークン、1 回 $0.25〜0.37)。

## 抽出の方法(`rules_extract.py`)

1. 条例+施行規則の清掃済み全文を、自治体ごとに1回の呼び出しで Claude(`claude-sonnet-5-5`、effort `medium`)に送る。全文でも入力は 3.6〜7.4 万トークン($0.07〜0.15)なので、章の切り出しはしていない(切り出しで根拠条文を落とすより、全文を渡して引用させる方が安全と判断)。
2. `schema.py` の形の JSON を作らせる。含む内容は、自家用広告物の定義と許可不要の基準(種類・区域ごとの面積/高さ/地上高)、禁止区域での自家用の扱い、許可が要る広告物の種類と閾値、許可期間、点検まわりの4つの義務(管理・点検・有資格者・報告。上の「4つの義務」)、禁止区域の概要(文のみ)。各項目に引用(条・項・号と原文100字以内)と confidence。
3. JSON が壊れている/スキーマ不適合なら、エラー文を添えて1回だけ作り直させる(失敗した生の出力は `runs/legal_failed_*.txt` に残る)。
4. **引用の機械照合**: 返った `quote` が原文に(空白差を除いて)そのまま在るかを検査し `quote_verified` を付ける。コミット済みの4ファイルは全引用が原文と一致した(4つの義務の再抽出後に数え直した: 東京都 43/43、埼玉県 39/39、越谷市 35/35、さいたま市 31/31)。ただし「引用が実在する」ことは「その引用から読んだ数値や解釈が正しい」ことの保証ではない。
5. `data/ordinances/rules_<自治体>.json` に保存。`status` は「AI抽出の第1版(検算前)」。

テストは `python3 -m unittest`(API は呼ばない。抽出の流れは偽クライアントで検査、保存済み JSON はスキーマと全引用の一致を検査)。

### 費用(2026-11-02 の実績)

最終版の4ファイルの抽出で $0.87、プロンプト調整の途中の実行を含む合計で約 $2.0(入力は `count_tokens` で事前に測れる: `extract --dry-run`)。料金は claude-api スキルの価格表(2026-10-06: Sonnet 5.5 入力 $2 / 出力 $10 per 1M)による概算。

## 店舗名 → 住所(`store_address.py`)

得意先住所は代理店経由だと看板の場所ではない(指示書の納品住所が入っているのは 29,034 件中 7 件)。店舗名(分かれば運営会社・都道府県)から公開情報で住所を引く。

```
python3 -m kanban_karte.legal.cli store-address "見本マート 架空店" [--operator 運営会社] [--prefecture 都道府県] [--ledger 台帳.sqlite] [--refresh] [--no-web] [--json]
```

1. **台帳** `sites` に同じ店舗名(空白・全半角を除いて一致)で住所があればそれ(確信度 1.0、API は呼ばない)。同名で住所が割れていれば 要確認。
2. **キャッシュ** `data/private/store_address_cache.json`(未追跡)。キーは 店舗名|運営会社|都道府県。`--refresh` で引き直す。
3. **Claude + web search**(サーバーツール `web_search_20250305`、1回 最大5検索)。公式の店舗一覧・店舗ページ、または地図サービスの公開ページを根拠にさせ、`address / source_url / source_kind / confidence / candidates[]` を JSON で返させる。
4. **確信度 < 0.7 は『住所 要確認』**(住所は最有力の候補として残し、他の候補は `candidates`)。さらに、モデルが返した出典 URL が**実際の検索結果に無い**ときは確信度を 0.5 に頭打ちにして 要確認(URL の作り話を弾く)。

費用は1件 $0.04〜0.10(トークン + 検索 $0.01/回)。テストは偽クライアント(実 API なし)。

**手動確認(実 API、5件、合計 $0.41)**:

| ケース | 結果 | 確信度 | 出典の種類 |
|---|---|---|---|
| 大手スーパーの店(会社・都道府県つき) | 確定 | 0.80 | other(店舗情報の掲載サイト。公式・地図は検索結果に出ず) |
| 別の大手スーパーの店(会社つき) | 確定 | 0.95 | official_store_list(公式の店舗ページ。地図サービス・店舗情報サイトと一致) |
| 宅配会社の営業所(都道府県つき) | 確定 | 0.85 | map_service(複数の地図サービスで一致。まとめサイトの別住所は古い情報として候補に回した) |
| 同名の「中央店」が複数県にある店(会社のみ) | 要確認 | 0.30 | 公式一覧。北本・本庄・三郷の3候補が出て決められない |
| 実在しない店名(近い名前の店はある) | 要確認 | 0.00 | なし。近い名前の店を候補に出しただけ |

- 『確定』は住所が**公開情報で店舗名と一致した**という意味で、看板の場所そのものの確認ではない(店舗の駐車場・別棟の看板などは住所が違うことがある)。
- 公式の店舗ページに店舗名完全一致の住所があるときだけ 0.9 以上になる。ポータルサイトだけだと 0.8 前後で、閾値(0.7)は超えるが公式ほど堅くない。確定の閾値を 0.85 に上げるかは本線の判断。

## 把握の数字の下ごしらえ: 件名から店舗名(`store_names.py`)

```
python3 -m kanban_karte.legal.cli store-names [--db signjobz.db] [--since 2022-01-01]
```

指示書の件名(SignJOBZ 複製 `r_shijisyo.sSHIJISYO`。読み取り専用で開く)から、店舗名らしい文字列を正規表現で抜く。母集団は **受注日が 2022-01-01 以降で件名に『点検』を含む 262 件**。店名に『店』が付かない件名が多い(チェーン名+地名+『点検』)ので、2通りで抜く。

- **チェーン名つき**: チェーン名(`data/private/store_chains.txt`、1行1つ、未追跡。顧客名なのでコード・docs には書かない)+ 地名 + (店|営業所|支店|センター|校)? で、後ろが空白・改行・『点検』等の語・文末。地名が数字で始まる(日付・回数)ものは除く。
- **『◯◯店』型**: チェーン名が分からなくても、2〜15 字 + 店|営業所|センター|校 で終わる語。

結果(2026-11-02): 262 件中 **136 件(51.9%)** で店舗名が取れた(チェーン名つき 106、『◯◯店』型 30。チェーン名は 15 件登録)。チェーン名の登録なしの『◯◯店』型だけだと 81 件(30.9%)。

- 取れなかった 126 件の大半は、ビル名・施設名・団体名・『屋上看板点検』のような件名で、店舗ではないので取れなくてよい。一方、チェーン名が登録に無い店(住宅・飲食・金融の支店など)は取りこぼす。チェーン名の登録を増やすと割合は上がる。
- 『◯◯店』型は誤取りがありうる(事業所名・モデルルーム等)。取れた = 店舗名と確定、ではなく、住所引き(`store_address.py`)の候補という位置づけ。
- 実際の住所引きは本線の GO 後。このコマンドは件数と割合だけ出し、名前は出さない。

## 検算(第2版、2026-11-02)

`python3 -m kanban_karte.legal.cli verify [--stamp]`(`verify.py`)。正解は手元の非公開データ(`data/private/sources.toml` の `[legal.verify]`)で、読むだけ。**値はこの repo にも出力にも書かない**(出力は件数と項目名だけ)。

方法は**粗い存在照合**: 正解ファイルは散文の Markdown / TSV なので、構造では比べない。自治体ごとの正解から「数字+単位」(㎡・m・年・月。漢数字も直す)を集め、`rules_*.json` の数値項目(面積・高さ・地上高・出幅・許可期間・点検の閾値)の値がその集合に在るかを見る。どの区域・種類の値かまでは見ないので、**一致は「正解にも在る値」というだけ**。正解に無い値は、さらに原文(条例・施行規則)に在るかで分ける。

| 自治体 | 一致 / 数値項目 | 正解に無い・原文に在る | 正解にも原文にも無い |
|---|---|---|---|
| 東京都 | 34 / 39 | 5 | 0 |
| 埼玉県 | 15 / 21 | 6 | 0 |
| 越谷市 | 14 / 20 | 6 | 0 |
| さいたま市 | 6 / 14 | 8 | 0 |
| 計 | 69 / 94 | 25 | **0** |

- 「正解にも原文にも無い」= 抽出の誤りの疑い、は **0 件**だったので、`rules_*.json` の数値は修正していない。status を「第2版(手元の正解と照合済み、一致 x/y)」にし、不一致の項目名を各 json の `verification` に残した。
- 4つの義務への分割後(2026-11-02)の再検算: 一致 69 のまま、数値項目が 93 → 94(旧 `inspection` の項目が 4 つの義務の項目に替わり、埼玉県の 4m 超が努力義務の層にも出るため +1)。新しい不一致は埼玉県の点検周期と 4m(正解に無く、原文に在る)で、旧版と同じ。
- 不一致 25 件は、正解が**その表を持たない**ことによるもの: 許可期間(東京都・埼玉県・さいたま市。正解は『許可期間は物理的な数値基準でない』として対象外)、点検の周期と対象の高さ(埼玉県)、禁止地域内の自家用の基準(越谷市・さいたま市の別表の禁止地域等の列)、東京都 別表第二の自家用の面積閾値(5㎡の項。10㎡は正解にも在る)。つまり**正解との突き合わせができなかった項目**で、正しいと確認できたのではない。
- 東京都 別表第二: 原文を読み直した。『上欄一から六までに掲げる地域地区等 合計が五平方メートル以下』『一以外に掲げる地域地区等 合計が十平方メートル以下』と文で書かれており、低層住居系だけでなく**中高層住居系・田園住居・風致・特別緑地・自然公園特別地域・第一種文教地区**が 5㎡。第1版はこの読みで抽出済み(変更なし)。ただし八の項(全域)にも『合計が五平方メートル以下』が平文で付いており、表のどの行に掛かるか決められない(`extraction_notes` に記載)。
- 東京都 別表第三: 別表第三だけを1回再抽出(`cli table3`、$0.073)し、`rules.permit_standards` に27件(広告塔の高さ、屋上の高さ、突出し広告の地上高・出幅、壁面の面積など)を足した。引用27/27が原文一致。この32の数値はすべて正解にも在る。**許可を受けるための基準**であって自家用の許可不要基準(別表第二)ではないので、judge では許可の要否には使わず、種類(`--kind`)が分かっていて高さ・地上高が基準を外れるときに注(`許可の基準(…)の…を外れる`)と根拠を出すだけ。条件(商業地域内か等)は項目ごとに別なので、該当する条件かの確認を促す文にしてある。

## 限界(必ず読む)

- **AI 抽出で、照合は粗い存在照合まで**(上の「検算」)。`rules_*.json` の数値をそのまま対外文書に使わない。
- 同じ条例でも実行ごとに抽出がゆらぐ(サンプリング指定が無いため)。実際に、東京都の施行規則 別表第二は表が崩れて平文になっており、住居系・商業系の区域の面積欄が空に読まれる回があった(プロンプトに「残り全部を指す行を展開する」旨を足して再抽出した版を採用)。東京都の `confidence` が 0.4〜0.6 と低いのはこのため。**東京都の自家用基準は特に要検算**。
- 越谷市・埼玉県・さいたま市のファイルは、上の調整の前のプロンプトで抽出した版。表の読み取りに自信が無い所は `extraction_notes` に残っている。
- 東京都 別表第三は `permit_standards` に展開したが、判定の要否には効かず注に出るだけ(上の「検算」)。電柱・鉄道沿線・空港の表は列が崩れていて対応づけに不確実さが残る(`table3_extraction.notes`)。
- 用途地域・禁止区域かどうかは**住所から引けない**(座標化・都市計画の地図データは扱わない)。設置場所の区分が分からないと、面積が閾値の間にある看板は 要実測 になり、`branches` に場合分けが出る。
- 景観計画区域・地区計画・広告協定地区・知事/市長の指定区域による個別の基準は見ていない。
- 点検の周期(年)が規則にあるのは埼玉県(3年)だけで、ほかの3つは `interval_years` が null(周期の規定が無い)。東京都は点検する義務の条文が見当たらない(grep で『定期』『点検』を確認。見落としがあれば `inspection_duty` を直す)。有資格者は『点検をさせる』ではなく『有資格の屋外広告物管理者を置く』(条例 第25条、規則 第2・3条。2026-11-02 に原文で確認し手で入れた。API の再抽出は未実施)。越谷市・さいたま市は『市長が必要ないと認めるもの』を除外に含むので、個別の免除は判定に出ない。
- 屋外広告物法(国)や、点検の様式改正(東京都 2026-04-01 施行の第2号様式)の扱いは見ていない。台帳の18項目の様式は `kanban_karte/ledger/items.py` が正本。
- 許可期間は「◯年以内」の上限。次回の許可期限の日付は台帳の許可書の日付から出す(この部品は期間の長さだけを返す)。
- 東京都以外の都道府県は未対応(都道府県名だけ返し、判定は 要実測)。
