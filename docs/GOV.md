# 行政の巡回一括登録+地図(gov)

行政の職員が街を歩いて撮った数百枚の写真を一括で上げると、位置で看板ごとに束ね、許可台帳と突き合わせ、1枚の地図に
「無許可の疑い(赤)/ 期限が近い(橙)/ 許可あり(緑)/ 位置なし(灰)」で出す。対象自治体は 東京都・埼玉県(越谷市・さいたま市を含む)。

デモでは自治体の許可台帳の代わりに、自社の施工台帳(看板カルテの台帳 `signs`)を使う。

```
写真フォルダ ─ intake ─→ 候補看板(gov_candidates)+ 位置なしの写真
                           │ geocode(国土地理院 逆ジオコーダ)→ 市区町村
台帳 signs ───── match ───┘ 30m 以内の最近傍 → 許可の状態・残り日数
                           └ map → 静的 HTML 1枚(Leaflet + 地理院タイル)
```

## 使い方

```
python3 -m kanban_karte.gov.cli intake <写真フォルダ> --db <台帳.sqlite>     # 束ねて保存+自治体の判定
python3 -m kanban_karte.gov.cli match  --db <台帳.sqlite> [--today 2026-11-02]  # 結果を表で見る
python3 -m kanban_karte.gov.cli map    --db <台帳.sqlite> --out map.html [--today ...]
python3 -m kanban_karte.gov.cli geocode --db <台帳.sqlite>                      # 通信できなかった分のやり直し
```

見本を作り直す(写真10枚・台帳5基。すべて架空):

```
python3 -m kanban_karte.gov.make_sample --db /tmp/gov.sqlite
python3 -m kanban_karte.gov.cli intake data/sample/gov/photos --db /tmp/gov.sqlite --geocache data/sample/gov/geocache.json
python3 -m kanban_karte.gov.cli map --db /tmp/gov.sqlite --today 2026-11-02 --out data/sample/out/map.html
```

`data/sample/out/map.html` は上の手順で作った物をコミットしてある(試験が「今のコードで作り直した物と同じ」を確かめる)。
`--today` は期限の判定に使う基準日で、既定は実行日。見本は 2026-11-02 に固定してある。

## 束ね方(batch_intake.py)

1. フォルダ(下位も)の JPEG / HEIC を読む。EXIF の GPS(緯度経度)と撮影時刻(DateTimeOriginal → DateTimeDigitized → DateTime の順)を取る。
   HEIC は任意依存の `pillow-heif`(`requirements-gov.txt`)が入っているときだけ読める。入っていなければ「読めない」として報告し、捨てたことを黙らない。
2. GPS が無い・範囲外・(0,0)(測位前に端末が書く既定値)の写真は **位置なし**。候補看板にはせず、1枚ずつ灰で一覧に出す。
3. 位置のある写真を撮影時刻順に1枚ずつ見て、既存の束の **重心から 15m 以内、かつ直前の撮影から 10 分以内** なら同じ束に入れる。
   両方に合う束が複数あれば近い方。無ければ新しい束。1束=1基の仮置き(候補看板)。時刻の無い写真は距離だけで判定する。
4. 同じ内容(sha256)の写真は取り込み済みとして飛ばす。同じフォルダを2回上げても二重にならない。
5. 保存先は台帳と同じ SQLite の `gov_batches / gov_candidates / gov_photos`(台帳のスキーマには触らない)。

半径(`--radius`)と撮影間隔(`--gap`)は変えられる。

## 自治体の判定(geocode.py)

国土地理院の逆ジオコーダ `LonLatToAddress` で緯度経度 → `muniCd`(5桁)を引き、`data/gsi/muni.csv`(国土地理院の市区町村コード表の複製。
出典と取得日は `data/gsi/README.md`)で自治体名にする。呼び出しは緯度経度を小数4桁(約10m)に丸めた値でキャッシュし、実際の通信は1秒に1回以下。
通信エラーはキャッシュせず「未判定」で残す(`geocode` で再実行)。海上・国外は「答えなし」としてキャッシュする。
対象は東京都・埼玉県(`in_scope`)。範囲外でも自治体名は表示し、ポップアップで注意を出す。
※ 判定は「どの自治体か」までで、その自治体の条例の中身(許可の要否・期間)は引かない。

## 突き合わせ(match.py)

候補看板の重心と台帳 `signs` の `lat/lng`(位置の無い看板は対象外)の距離を測り、**30m 以内で最近傍の1基** に一致させる。無ければ「台帳に無い」。

| 状態 | 色 | 条件 |
|---|---|---|
| 台帳に無い(無許可の疑い・要確認) | 赤 | 30m 以内に台帳の看板が無い |
| 許可期限切れ | 赤 | `permit_expires` が基準日より前 |
| 期限が近い | 橙 | 残り 0〜90 日(`--warn-days`) |
| 台帳に有るが許可の要否・期限が未記入 | 橙 | 期限が空で `permit_required` が空または「要」 |
| 許可あり | 緑 | 残り 91 日以上 |
| 許可不要(台帳) | 緑 | 期限が空で `permit_required` が「不要」 |
| 位置なし | 灰 | GPS の無い写真 |

期限が入っていれば期限で判定し、無ければ `permit_required` で判定する。残り日数は `permit_expires - 基準日`(当日=0、超過は負)。
更新手続きの目安日は「期限の 90 日前」を表示するが、**この画面の設定値で条例の定めではない**。

## 地図(map.py)

Leaflet 1.9.4(cdnjs・SRI 付き)の静的 HTML。タイルは国土地理院タイル「淡色地図」で、出典(地理院タイル)を地図右下と本文に出す。
(OpenStreetMap の標準タイルは使っていない。)凡例に色ごとの件数、内訳、要対応(赤・橙)の一覧、位置なしの写真の一覧、
台帳の看板のうち今回写っていなかった基数を出す。件数は HTML 本文に直接書いてあり、スクリプトが動かなくても読める。
データは JSON で埋め込み、ポップアップは textContent で組むので、看板名やファイル名に HTML が入っても崩れない。

## 限界

- **許可台帳の代用**: 本物の自治体の許可台帳は使っていない。自社の施工台帳は自社が施工した看板しか載らないため、
  「台帳に無い」は「自社の施工台帳に無い」でしかない。実運用では自治体の許可台帳(許可番号・期限・申請者)に差し替える。
  「台帳に無い」は無許可と決まったという意味ではなく、現地確認の対象という意味。
- **位置精度**: スマートフォンの GPS は市街地(高い建物の間)で 10〜30m ずれることがある。15m の束ね半径と 30m の一致半径は目安で、
  実データで調整が要る。隣り合う2基(同じ店の袖看板とポール看板など)は 15m 以内だと1束になる。
  ずれのせいで、同じ看板が別の束に割れる/ 別の看板に一致する、も起こりうる。
- **束ねは時刻の近さを使う**: 同じ看板に後で戻って撮ると別の束になる。逆に、10 分以内に 15m 以内の別の看板を撮ると同じ束になる。
- **向き・高さを見ていない**: 写真の向き(GPS の方位)・看板の高さは使っていない。道路の反対側の看板も距離だけで一致しうる。
- **束ねの範囲は取り込み単位**: 別の取り込みで上げた写真同士は束ねない(同じ看板が2つの候補になりうる)。
- **撮影時刻にタイムゾーンが無い**: EXIF の時刻は端末の現地時刻のまま比較する(複数端末の時計ずれは見ていない)。
- **自治体の判定は通信が要る**: 通信できなければ未判定のまま残る(地図は出る)。国土地理院の応答は使用側で保証されない。
- 候補看板が写真の見た目で本当に同じ看板かは見ていない(画像認識はしない)。
