# 様式出力(台帳 → xlsx)

台帳(SQLite)の現場1件から、2種類の xlsx を出す。**出力は常に下書き**。有資格者が確認・署名するまでは正式な報告書ではない(バナー・印刷ヘッダ・斜めの透かしで示す)。AI は点検の判定を確定しない。台帳に入っている有資格者の確定値を並べるだけで、無い項目は空欄にして赤字で「未判定」と出す。

```
python3 -m kanban_karte.output.cli tokyo    --site <現場ID> --out out.xlsx   # 東京都 第2号様式
python3 -m kanban_karte.output.cli client-a --site <現場ID> --out out.xlsx   # 客先A型(センター単位)
# 台帳は --db(既定 data/private/ledger.sqlite、KANBAN_KARTE_DB)。見本データなら --from-json data/sample/ledger.json
```

見本の出力は `data/sample/out/`(架空の店名。様式を変えたら作り直す。テストが現行コードの出力と突き合わせる)。依存は `requirements-output.txt`(openpyxl, pillow)。

## 共通の約束

- 日付は YYYY-MM-DD。入力欄の見出しにも書く。
- 黄色の欄は人が記入する欄(報告者・点検実施者・署名など。台帳に無い)。
- 赤字「未判定」は台帳にデータが無いもの。「良好」などに黙って補わない。
- 写真は長辺 640px 以内に縮小した JPEG でセルに埋め込む(拡大しない)。最大6枚。7枚目以降は省略し、省略したことを注記する。開けない写真は赤字で注記する。
- 透かしは日本語フォントが見つかる環境で入る(Mac / Windows / Noto CJK。`KANBAN_KARTE_FONT` で指定可)。無い環境ではバナーと印刷ヘッダだけになる。

## (1) 東京都 屋外広告物安全点検報告書 第2号様式

様式の原文は都の様式 PDF(2026-04-01 施行、2026-11-02 に原文を確認)。構造: 報告者・屋外広告物管理者(資格つき)・種類・場所・設置年月日・点検年月日・前回許可年月日と番号、18項目 × 4区分(良好 / 経過観察 / 要改善 / 対象外)に○、「異常の内容と改善の内容」。裏面の注: 要改善は補修したうえで内容を記入、写真(全景・表示面、要改善は補修前後)を様式任意で添付。**原文に「総合所見欄」「写真欄」は無い**ので、総合判定と所見は表の下に、写真は別シートに足した。

看板1基につき2シート: `様式_<看板ID>` と `写真_<看板ID>`。

| 様式のセル | 台帳の列 | 備考 |
|---|---|---|
| 報告日 | なし | 入力欄 |
| 報告者(住所・氏名・電話) | なし | 入力欄 |
| 屋外広告物管理者(住所・氏名・電話・資格) | なし | 入力欄。資格は有資格者が記入 |
| 広告物等の種類 | signs.type | 空なら未判定 |
| 表示又は設置の場所 | signs.address(空なら sites.address) | 空なら未判定 |
| 設置年月日 | なし | 入力欄(不明なら最初の許可年月日、と様式の注3) |
| 点検年月日 | signs.last_inspected | 空なら未判定 |
| 前回許可年月日・番号 | なし | 入力欄 |
| (台帳の確認行) | signs.id, name, size_w, size_h | 様式にない小さな注記 |
| 点検結果 ○ の位置(18行) | signs.items[点検項目キー] | 良好 / 経過観察 / 要改善 / 対象外 の列に ○。キーが無ければ4列とも空で右欄に赤字「未判定」 |
| 異常の内容と改善の内容 | (台帳に項目別の欄が無い) | 経過観察・要改善の行に「要記入」(黄色)。有資格者が書く |
| 総合判定(様式外) | signs.rank | 「3 要改善」の形。空なら未判定 |
| 総合所見(様式外) | signs.remark | 空なら黄色の入力欄 |
| 点検実施者 氏名・資格・署名日 | なし | 入力欄(様式外) |
| 写真シート | signs.photos | 2列×3段、最大6枚 |

18項目の行の並びと項目名は `kanban_karte/ledger/items.py`(様式の原文)に一致。

## (2) 客先A型: センター(現場)単位の安全点検報告書

客先の実ファイルは見られないので、依頼の構成どおり自前に設計した(社名・ロゴなし)。シート: `表紙` / `看板一覧` / `看板_<看板ID>`(アイテム別の写真ページ。ここでの「アイテム」を看板1基と読んだ)。

評価 A=良好 / B=経過観察 / C=要改善 / D=即時対応。

| セル | 台帳の列 | 規則 |
|---|---|---|
| 表紙: 現場名 / 所在地 | sites.name / sites.address | |
| 表紙: 調査日 | signs.last_inspected | 看板の日付が1つならその日、複数なら「最小 〜 最大」 |
| 表紙: 総合評価 | signs.rank | 看板の rank の最悪(1→A … 4→D)。1基でも rank が空なら「未判定」(確定済み分の最悪を添える) |
| 表紙: 内訳 | signs.rank | 総合評価ごとの基数と未判定の基数 |
| 一覧: 種類 / 寸法 | signs.type / size_w, size_h | |
| 一覧: 腐食 / 破損 / 固定 | signs.items | 下の視点表。当たる項目の最悪(良好=A 経過観察=B 要改善=C)。項目が全て対象外なら「-」、判定済みが無ければ「未判定」、一部だけなら「B(暫定)」と赤字 |
| 一覧: 総合 | signs.rank | 1→A 2→B 3→C 4→D。空なら未判定 |
| 一覧: 前回との差 | signs.prev_rank と rank | 変化なし / 悪化 / 改善 / 前回なし |
| 一覧: 所見 / 写真 | signs.remark / signs.photos | 写真は載せた枚数(最大6) |
| 一覧: 未判定項目 | signs.items | 18項目のうち記入の無い数 |
| 看板ページ: 18項目の判定 / 評価 | signs.items | 判定は原文の区分、評価は A〜C(対象外は「-」)。無ければ赤字「未判定」 |
| 看板ページ: 写真 | signs.photos | 2列×3段、最大6枚 |

D は点検項目の区分に無い(項目は良好 / 経過観察 / 要改善 / 対象外の4つ)ので、項目からは出さず、rank 4 の看板の総合にだけ付く。

視点表(自前の割り当て。1項目が複数の視点に入る。どの項目もどれかに入る):

| 視点 | 点検項目キー |
|---|---|
| 腐食 | 基礎部・上部構造-3, 支持部-1, 取付部-1, 表示部-1, 表示部-2, 表示部-3, 照明装置-2, その他-1, その他-2 |
| 破損 | 基礎部・上部構造-2, 支持部-1, 取付部-2, 表示部-1, 表示部-2, 表示部-4, 照明装置-1, 照明装置-2, 照明装置-3, その他-1, その他-2, その他-3 |
| 固定 | 基礎部・上部構造-1, 基礎部・上部構造-2, 支持部-2, 取付部-1, 取付部-3, 表示部-1 |

## できていないこと

- 実機(Excel)での見た目の確認。この環境には xlsx の描画ソフトが無く、openpyxl で読み戻して値・位置・画像の数を検査した。行の高さ・折り返し・透かしの重なりは、Excel で開いて見直しが要る。
- 台帳に無い情報(報告者・管理者・設置年月日・前回許可・項目別の異常内容・写真の説明と補修前後の区別)は入力欄のまま。台帳に列を足すかは本線の判断。
- 客先A型の視点表と A〜D の対応は自前の案。客先の実様式が分かれば差し替える(`client_a_form.PERSPECTIVES` 1か所)。
